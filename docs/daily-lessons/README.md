# AI Infra 每日讲义编写与学习执行规则

## 1. 适用对象与默认前提

每日讲义默认读者：

- 了解 Python、PyTorch 或 C++ 的基础语法；
- 使用过模型，但没有系统学习模型训练与推理的数据流；
- 不默认掌握线性代数记号、张量 shape、Attention、GPU 或分布式训练；
- 希望最终能够把理论、代码、性能实验和面试表达连接起来。

因此，讲义不得用公式替代解释，也不能以“这是常识”为由跳过基础概念。

## 2. 每个知识点的强制讲解顺序

每个首次出现的知识点必须按以下顺序编写：

1. **它要解决什么问题**：先说明为什么需要它。
2. **生活化或可视化直觉**：不用公式解释大致过程。
3. **极小具体例子**：优先使用 1–3 个 token、2 个 head 或小矩阵。
4. **术语与符号表**：解释每个字母、下标、缩写和运算符。
5. **逐步数据流**：说明输入从哪里来，每一步产生什么。
6. **逐步 shape 变化**：说明每一维代表什么、哪一维被保留或变换。
7. **正式公式**：只有在机制已经解释后才给出公式。
8. **对应代码**：指出代码如何构造、变换和验证这些张量。
9. **AI Infra 影响**：说明参数、激活、FLOPs、内存、带宽或通信如何变化。
10. **常见误解与边界**：明确容易混淆和不总成立的结论。
11. **最小验证**：给出手算题、代码测试或实验。
12. **口述总结**：给出 30 秒和 2 分钟表达目标。

如果一段内容只有已经理解该概念的人才能看懂，就不符合讲义标准。

## 3. 符号与公式规则

- 任何符号首次出现时必须紧邻解释，不能只在文档开头给一张表后长期默认记忆。
- 数学公式统一采用 Markdown+Math 默认的 `dollars` 定界符：行内公式使用 `$...$`，块公式使用 `$$...$$`，不使用 `\\(...\\)` 或 `\\[...\\]`。
- 数学环境中的下标直接写成 `g_1`，不要写成 `g\\_1`；块公式前后必须保留空行。
- 简单等式和多步算术优先使用普通文字或 `text` 代码块，只有确实需要分数、求和、矩阵等数学排版时才使用 LaTeX 命令。
- 写 `X[B,S,H]` 时，必须说明 `X` 是什么，`B/S/H` 分别对应现实中的什么。
- 写 `@`、`×`、`Σ`、转置、reshape、transpose 等操作时，必须解释操作含义和是否改变数值。
- 正式大配置前必须先给一个人脑可手算的小配置。
- 不能把逻辑 shape 直接写成物理存储事实；如果实现可能使用 view、broadcast、fusion 或不物化中间张量，必须说明。
- 不能用“主要包括”“大致如此”掩盖事实边界；具体模型或框架有差异时明确标注。

## 4. 代码规则

- 代码首先服务于验证理论，不以代码行数或框架复杂度体现深度。
- 每段关键代码前说明输入、输出和预期 shape。
- 关键 shape 使用断言验证，不能只依赖打印。
- 正确性实验先于性能实验。
- 代码输出必须在当前环境实际运行后写入结论。
- 如果算子或后端不支持，要区分明确失败、CPU fallback 和性能退化。

## 5. 实验与事实规则

- 每个实验必须有 baseline 和单一主要变量。
- 记录硬件、软件版本、dtype、batch、sequence length、warmup 和测量方法。
- 区分理论估算、框架统计、profiler 观测和工程推断。
- 命令退出成功不等于结论成立；还要验证输出、shape、状态或指标。
- 至少保留一个优化无收益或结果不符合预期的案例，并解释原因。
- 不把 CUDA 上的经验直接写成 MPS 或其他硬件上的确定结论。

## 6. 每日讲义固定结构

每份 Day 文档按以下标题组织：

1. 今日核心问题
2. 前置知识与术语
3. 从直觉到机制
4. 极小手算例子
5. 正式模型配置
6. 完整数据流与 shape
7. 参数、内存与计算成本
8. 最小代码验证
9. 常见误解与边界
10. 手算练习
11. 面试口述
12. 当日验收

标题可以因主题微调，但不能缺失讲解、代码、边界和验收四类内容。

## 7. 每天如何开展

每天采用固定闭环，避免只阅读不验证：

1. **昨日回忆（10–15 分钟）**：不看资料回答昨日三个核心问题。
2. **今日问题（5 分钟）**：明确今天最终要解释的一个完整问题。
3. **理论讲解（45–60 分钟）**：只学习支持今日问题所需的概念。
4. **手算与画图（30–45 分钟）**：写 shape、状态、内存或数据流。
5. **最小代码（60–120 分钟）**：用最少代码验证理论。
6. **实验解释（30 分钟）**：记录预期、实际结果、差异和未知项。
7. **面试口述（15 分钟）**：分别用 30 秒和 2 分钟回答。
8. **当日验收（10 分钟）**：未通过则次日先补缺口，不把“看完”记为掌握。

每天建议投入 3–5 小时。时间不足时，优先保留手算、代码和验收，压缩扩展阅读。

## 8. 每天的固定产物

每个 Day 目录至少保留：

- 一份讲义；
- 一份手算题；
- 一个最小可运行程序；
- 一份实验结果；
- 三道口述题；
- 一项尚未确认的问题。

代码运行结果和实际答案必须来自当天环境，不凭记忆填写。

## 9. 每日完成定义

只有同时满足以下条件才标记完成：

- 能不看资料画出当天核心数据流；
- 手算题正确；
- 最小代码能够运行；
- 能解释代码结果为什么合理；
- 能说出至少一个失效条件或边界；
- 能完成 2 分钟口述。
